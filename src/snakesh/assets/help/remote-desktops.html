Remote Desktops

SnakeSh supports RDP and VNC sessions through integrated launch workflows. These sessions still live in the session library, but their runtime behavior is different from terminal tabs because desktop viewers do not share a universal input API.

RDP

  • Windows uses mstsc.
  • Linux uses xfreerdp.
  • Linux can run supported RDP sessions inside SnakeSh tabs or as detached viewers.
  • The Open Mode field appears only on Linux; non-Linux RDP is always detached.
  • Saved credentials and RDP domain values can be applied where supported.

VNC

VNC uses an installed platform viewer such as TigerVNC or compatible alternatives. SnakeSh detects available viewers and applies display preferences when the selected client supports them.

Display Preferences

RDP and VNC sessions can store options such as resolution, fullscreen, and color depth. These settings stay attached to the session definition so reconnects use the same viewing preference each time.

For the native macOS SDL RDP viewer, Default and fixed resolutions scale the desktop as its window is resized. Auto requests changes to the remote desktop resolution and requires server display-control support.

The native macOS SDL viewer maps both Command keys to remote Ctrl, so Command-C and Command-V use the remote application's Ctrl-C/Ctrl-V bindings. Other Command combinations also act as remote Ctrl combinations. For Linux terminals that use Ctrl-Shift-C/V to copy and paste, use Command-Shift-C/V.

Automatic RDP Resize Recovery

On Linux and macOS, SnakeSh detects the known FreeRDP error where an already connected desktop closes during an Auto resolution change. It makes one reconnect attempt with smart sizing. The viewer briefly closes and restarts; you may need to sign in again. Smart sizing lets you resize or maximize the window while keeping the remote desktop at a fixed resolution.

A popup appears once for the recovered connection, explains what happened, and suggests supported client/server updates. The tab continues to show the smart-sizing fallback. For affected older xrdp servers, a distribution repository update containing the resize fix from xrdp 0.10 or later may restore Auto. The fallback applies to the current connection; opening a new connection retries Auto.

This recovery handles the recognized resize error. Login failures, normal disconnects, user cancellations, and unrelated client exits keep their normal behavior. If the reconnect fails, SnakeSh reports it without repeatedly restarting the viewer.

Clipboard-Oriented Fast Commands

Saved Fast Commands behave differently on remote viewer tabs. Instead of trying to type into the remote desktop, SnakeSh copies the command text to the local clipboard and tells you to paste it manually inside the remote session. This keeps the behavior predictable across viewer implementations.

Platform Limits

Linux X11 RDP tabs track the FreeRDP child window directly. Default and fixed desktop resolutions scale to the tab; Auto requests remote resolution changes. A temporary missing window lookup does not detach a running viewer. When a client exits, its recent error output is displayed in the tab.

Changed RDP Certificates

When FreeRDP reports a changed saved certificate, SnakeSh displays the previous and new SHA256 fingerprints. Verify the new fingerprint with the server administrator before accepting. The default is No. Accepting updates only that host and port's matching saved fingerprint and reconnects; refusing preserves the saved certificate.

Not every protocol supports in-tab rendering on every operating system. When a viewer must run detached, SnakeSh still manages the session entry and launch flow, but the actual desktop surface opens through the platform viewer process. See Platform Differences in the Help index for a direct Windows, Linux, and macOS comparison.

macOS RDP

SnakeSh prefers an installed native FreeRDP SDL client, which does not need XQuartz. Older X11-only installations use xfreerdp with a working XQuartz display. If XQuartz cannot provide a display, SnakeSh reports an error.
